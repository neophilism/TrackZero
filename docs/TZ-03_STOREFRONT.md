# TZ-03 station identity and storefront shell

The current branch validates public station metadata and renders an accessible, static catalog preview. It escapes all station and offer text, renders artwork only from configured HTTPS origins, and never shows purchase or playback controls. An empty catalog has an explicit status. A SQLite-backed catalog and framework-neutral HTTP handler persist public metadata only. Publishing requires a server-verified artist or label identity, the same scoped owner on updates, and an injected offer-rights verifier. Public reads use a restrictive content security policy. `node --test tests/*.test.mjs` covers normal use, denial, owner/tenant isolation, hostile text and URLs, restart recovery, and interrupted writes locally.

This is an inert shell with dependency-injected authorization boundaries. No configured identity provider, production rights verifier, deployed durable database, payment flow, entitlement, streaming access, or production release exists in this repository. The original TZ-03 plan depends on TZ-02, whose provider and engine integration is incomplete; imported registry dependencies are empty and do not establish that acceptance. The existing planning CI does not run this product test suite, and its configuration is a protected path under the Boardroom gateway.
