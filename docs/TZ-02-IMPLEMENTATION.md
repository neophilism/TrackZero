# TZ-02 onboarding implementation status

The current branch adds a local, durable onboarding core. `src/onboarding.mjs` stores only an opaque provider subject, tenant/application scope, role grants and hashed one-time invitations in SQLite. A trusted authentication adapter supplies the verified subject; the HTTP handler rejects client-asserted identity fields and cross-origin writes. Listener enrollment is self-service. Artist and label grants require a scoped, unexpired invitation provisioned outside the public handler. Reopening the database and reauthenticating the same provider subject recovers the same account. Transactions roll back incomplete account and role writes.

Run `node --test tests/onboarding.test.mjs` with Node 24. The tests cover first enrollment, duplicate replay, restart recovery, cross-tenant/application/subject isolation, role-specific invitation denial, token reuse, expiry, unauthenticated requests, cross-origin requests and an injected write interruption. The existing CI configuration does not run this new suite; its protected path could not be changed through the current fenced gateway.

This is a software core, not a production login service. The repository has no configured identity provider, deployed durable database, or direct Distributed Radio Engine adapter. The source-backed Coffee answer for thread `5d930d25-c2bf-4f54-898b-d2262ee331e1` describes `makeMembership`, `authorizeStationAction`, and `validateRecipientAuthorization` in DRE-02, but the exact exported code and production endpoint grant have not been independently verified in this TrackZero assignment. Do not treat account login or a role grant as decrypting-device enrollment. Before integration acceptance, connect an authenticated provider and an authorized durable database, verify the immutable engine contract, and test TrackZero's adapter against that contract. No hardware, field, E2EESA, or production release evidence is claimed.
